# PENTAPHOR Android 설계

작성일: 2026-09-29. 상태: 사용자 승인 완료. 구현 계획 검토 후 착수.

## 목적과 승인된 방향

기존 iOS 앱을 유지하면서 같은 저장소의 `android/`에 Kotlin + Jetpack Compose 네이티브 앱을 추가한다. 기존 디자인과 동작을 안드로이드에서 재현하고, 직접 설치해 사용할 수 있는 APK를 제공한다. 사용자는 같은 저장소에 안드로이드 앱을 추가하는 방향과 아래 명세를 승인했다. 아직 안드로이드 구현은 시작하지 않았다.

완료 기준은 빈 프로젝트 생성이 아니라 퀘스트 생성·수정·달성, 파라미터 성장, 알림, 주간 정산, 파일 백업·복원을 실제로 사용할 수 있는 앱이다. 첫 배포는 APK 설치 방식으로 가정한다. Google Play 계정 생성이나 공개 배포는 범위에 포함하지 않는다.

## 기술 선택

선택한 방식은 Kotlin + Jetpack Compose다. iOS 코드를 Flutter/React Native로 다시 작성하는 방식은 기존 기능과 연출에 대한 회귀 부담이 크다. Kotlin Multiplatform 도입도 현재 Swift 도메인을 그대로 공유하지 못하므로 첫 안드로이드 버전에는 도입하지 않는다. 대신 기존 Swift 명세와 테스트 사례, 공통 백업 형식으로 동작의 일관성을 검증한다.

- `android/core`: Android API에 의존하지 않는 Kotlin 도메인, 날짜 계산, 정산, 백업 코덱. JVM 단위 테스트가 가능해야 한다.
- `android/app`: Compose 화면, ViewModel, 파일 저장, 알림, 햅틱, Android 생명주기 연결.
- 기존 `assets/`와 iOS 에셋의 최종본을 재사용한다. 빌드에서 필요한 아트만 Android 리소스로 복사하고, 원본과 대응하는 목록을 관리한다.
- Gradle Wrapper와 버전 카탈로그로 의존성을 고정한다. 공식 호환표에 맞는 안정 버전의 JDK·AGP·Kotlin·Compose 조합을 구현 계획에서 확정한다.
- 최소 Android 8.0(API 26)을 지원한다. target/compile SDK는 구현 시 설치 가능한 최신 안정 SDK로 고정한다.
- 앱 ID는 `app.pentaphor.personal`, 표시 이름은 PENTAPHOR로 한다. 플랫폼별 서명은 별개다.

서버·로그인·자동 동기화는 추가하지 않는다. iOS 소스와 서명·배포 설정은 변경하지 않는다.

## 상태와 저장 경계

기존 AppState의 퀘스트, 완료 기록, 설정, 타임존, 정산 확인 시점을 보존하는 모델을 사용한다. 앱 전용 저장소의 JSON 파일에 원자적으로 저장한다. 첫 버전에서는 같은 상태를 별도 데이터베이스와 이중으로 관리하지 않는다.

ViewModel은 화면 상태와 사용자 의도를 전달하고, 도메인이 후보 상태를 계산한다. 저장이 성공한 뒤에만 새 상태를 화면에 게시하고 햅틱·달성 연출·알림 재예약을 실행한다. 쓰기 실패는 기존 파일과 메모리 상태를 유지하고 사용자에게 알려준다. 변경 작업은 직렬화하여 중복 탭과 복원 중 갱신이 충돌하지 않게 한다.

첫 실행의 기기 타임존을 상태에 저장한다. 이후 날짜 계산은 저장된 타임존으로 실행한다. 잘못된 타임존의 백업은 거부한다. 여행으로 기기 타임존이 바뀌어도 과거 기록의 구간을 임의로 재해석하지 않는다.

## 기능과 도메인 동등성

### 퀘스트

- 체력·지식·끈기·매력·용기 5종. 퀘스트 보상 총합은 최대 2이며 기존 iOS 검증 규칙을 따른다.
- 일회성·주간·월간을 지원하며, 활성 목록은 주기별로 분리하지 않는다.
- 이름, 메모, 아트, 목표 횟수, 보상, 알림을 생성·수정할 수 있다. 목표는 1~99, 일회성은 1이다.
- 아트 선택은 이름이나 힌트를 변경하지 않는다. 카테고리는 아트 선택기 안에서만 표시한다. 아트 이름은 표시하지 않는다.
- 보관과 삭제 모두 기존 기록·획득 파라미터를 유지한다. 삭제한 퀘스트는 일반 목록에서 숨긴다.
- 한 번이라도 기록이 있으면 취소한 기록만 남아 있어도 주기를 변경할 수 없다.
- 목표 수정은 현재 구간에 즉시 적용한다. 현재 구간 완료 기록의 목표 스냅샷도 갱신하지만 기존 보상, 시각, ID, 취소 여부와 과거 구간 목표는 보존한다.
- 완료 취소는 기록의 취소 상태를 변경하고 합계·보너스를 다시 계산한다. 같은 완료 요청 ID의 재전송은 중복 보상을 만들지 않는다.

### 날짜와 끈기

새 주는 월요일 00시에 시작한다. 월요일 09시 전에는 명시적으로 지난주에 기록할 수 있다. 현재 활동을 자동으로 지난주에 넣지 않는다. 월간은 달력상의 월을 기준으로 한다.

주간 또는 월간 목표를 연속 2구간 이상 달성하면 두 번째 구간부터 각 연속 구간마다 끈기 1을 더한다. 이 보너스는 기록에서 계산하며 별도로 중복 지급하지 않는다. 일회성에는 연속 보너스가 없다. 취소·목표 수정·복원 후에도 같은 규칙으로 다시 계산한다.

기간 계산은 DST, 연말, 윤년, 월요일 08:59/09:00 경계를 테스트한다. Swift의 요일 번호(일요일=1)와 Java의 요일 번호 차이를 백업 및 알림 경계에서 명시적으로 변환한다.

### 화면과 연출

기존 온보딩, 닉네임, 메인 목록, 퀘스트 에디터, 아트 선택기, 달성 화면, 보관 목록, 설정, 정산 화면을 옮긴다. 기존 크림색·짙은 잉크색·청록색·금색 팔레트와 최종 오각형 로고, 60종 아트를 재사용한다. 새로운 로고나 아트는 만들지 않는다.

슬로건은 `STACK YOUR PROGRESS`와 `작은 행동을 쌓아, 나를 키우다`다. 일반 제품 문구는 기존 말투를 유지하고 앱 정보·데이터 안내는 존댓말로 작성한다.

오각형은 각 파라미터가 독립적으로 성장한다. 한 축의 증가가 다른 축을 축소하지 않는다. 달성 시 증가한 꼭짓점을 강조하고 튀어나오는 연출과 실제 햅틱을 연결한다. 시작 화면은 최소 한 사이클의 성장 연출을 보여준다. 달성 연출 간소화 설정으로 시작 연출을 끄지 않는다. 시스템의 애니메이션 제한은 별도로 존중한다.

TalkBack 설명, 글자 확대, 터치 영역, 대비, 뒤로 가기 및 화면 회전·프로세스 재생성을 확인한다. 에디터 입력 초안은 구성 변경으로 잃지 않도록 저장한다.

### 주간 정산

저장된 타임존의 월요일 09시 이후 앱 실행 또는 포그라운드 복귀 시 표시한다. 아직 확인하지 않은 가장 최근의 마감된 비어 있지 않은 주를 대상으로 한다. 편집·달성·복원 등 다른 흐름이 열려 있으면 끝난 뒤 표시한다.

완료 횟수, 활동과 파라미터 증가량, 끈기 보너스를 게임 보상 화면처럼 보여준다. 정산을 열거나 다시 보는 행위가 보상을 지급하지 않는다. 주간 기록은 기록에 저장된 구간을 따르고, 월간·일회성 활동은 실제 기록 시각으로 해당 주를 계산한다. 확인 시점은 저장하고 과거 정산도 다시 볼 수 있게 한다.

### 알림

퀘스트별 여러 요일과 하나의 시간을 지원한다. 목표를 채우면 해당 구간의 나머지 알림을 억제하고 다음 구간에는 다시 활성화한다. 일회성은 완료하면 더 알리지 않는다. 완료·취소·수정·보관·삭제·복원·설정 변경 시 재계산한다.

Android 알림 채널과 OS 알림 권한을 사용한다. 앱 설정 토글은 앱의 선호와 OS 권한을 함께 반영하고, OS가 막으면 설정 화면으로 안내한다. 실제 테스트 알림을 제공한다.

첫 버전은 정확한 알람 특별 권한을 요구하지 않는 일반 예약 알림으로 설계한다. AlarmManager의 다음 알림과 주기 갱신을 예약하고, 수신 시 최신 저장 상태를 읽어 달성 여부를 다시 검증한다. WorkManager는 예약 복구를 보조한다. 재부팅·시간/타임존 변경·앱 업데이트·앱 복귀 시 예약을 복구한다. 절전 상태에서는 지정 시각보다 지연될 수 있음을 설정에 간결하게 설명한다. 최근 앱 목록에서 제거한 경우와 OS에서 강제 종료한 경우를 구분하며 강제 종료 상태의 수신을 보장하지 않는다.

참고: [Android 알람 문서](https://developer.android.com/develop/background-work/services/alarms), [정확한 알람 권한](https://developer.android.com/about/versions/14/changes/schedule-exact-alarms).

## 백업과 복원

기존 `.pentaphor` 형식 v1을 그대로 읽고 쓴다. envelope의 appID, formatVersion, createdAt, Base64 payload, SHA-256 checksum을 유지한다. 날짜는 Swift Codable의 2001-01-01 기준 초 표현과 호환되어야 한다. checksum은 파싱·재직렬화한 값이 아니라 실제 payload 바이트로 검증한다. 전체 파일 20 MiB 제한 및 기존 상태 검증을 적용한다.

일회성 구간의 Swift distantPast/distantFuture, 선택 필드의 생략, UUID 표현, 소수 초, 취소 기록, 삭제 기록과 구간별 목표 스냅샷을 실제 Swift 생성 fixture로 고정한다. Swift→Kotlin 및 Kotlin→Swift 양방향 복원 테스트를 통과해야 한다.

Android에서는 Storage Access Framework로 사용자가 외부 저장 위치를 선택한다. Google Drive 제공자가 설치되어 있으면 해당 위치도 선택할 수 있다. iCloud 전용 API나 Google Drive 자체 로그인은 추가하지 않는다. iOS와 Android 사이에는 파일을 수동으로 옮긴다. Android의 자동 앱 백업으로 별도 복원이 섞이지 않도록 초기 버전은 사용자 실행 파일 백업을 복원 경로로 명확히 한다.

복원 전 검증과 미리보기, 현재 상태의 안전 사본 저장, 전체 교체 확인을 제공한다. 쓰기 실패 시 기존 상태를 유지한다. 복원 후 화면·정산·알림을 갱신한다. 앱 전용 안전 사본은 앱 삭제를 견디지 않으므로 외부 백업과 구분해 안내한다. 파일 제공자에 쓰기가 끝났다는 사실과 원격 클라우드 업로드 완료를 혼동하지 않는다.

참고: [Android 문서 저장 및 선택](https://developer.android.com/training/data-storage/shared/documents-files).

## 검증과 납품

구현은 실패하는 도메인 테스트부터 작성하고, 실제 동작을 구현하여 통과시키는 순서로 진행한다. Swift 테스트의 기대값을 기준으로 공유 fixture를 만들되 Android 구현이 스스로 생성한 값만 검증하는 테스트는 피한다.

1. 순수 JVM 테스트: 기간·보상·목표 수정·취소·보관·삭제·연속 보너스·정산·알림 후보·백업 검증 및 실패 시 상태 보존.
2. Compose/기기 테스트: 온보딩→생성→달성→수정→취소, 아트 독립성, 목표 14 표시, 정산의 포그라운드 진입, 설정, 백업 미리보기·복원.
3. 플랫폼 확인: OS 권한 거부/허용, 앱 재시작·프로세스 종료·재부팅 후 알림, 파일 제공자 취소/실패, 작은 화면·글자 확대·애니메이션 제한.
4. 배포 확인: Android lint, JVM 테스트, 에뮬레이터 테스트, 서명된 APK 생성 및 설치 후 핵심 흐름 확인. 실제 안드로이드 폰의 햅틱·제조사 절전 영향은 폰을 확보하지 못하면 미검증 항목으로 명시한다.

현재 개발 머신에는 Java Runtime과 Android SDK가 없다. 구현 단계에서 사용자 홈 아래 개발 도구를 설치하고 버전을 기록한다. 서명 키는 `~/.config/deploy-credentials/android/pentaphor/`에 보관하고 저장소에 넣지 않는다. 동일 키와 증가하는 versionCode로 후속 설치가 기존 데이터를 유지하도록 한다. 암호나 키 내용은 로그에 출력하지 않는다.

납품물은 APK, 설치 방법, 테스트 결과와 실제 검증 범위다. Android만 바뀌면 iOS 바이너리가 달라지지 않으므로 TestFlight를 재배포하지 않는다. 향후 iOS 앱 변경이 포함되면 기존 `Personal` 내부 배포 절차를 그대로 적용한다.

## 구현 분할

하나의 Android 포팅 작업 안에서 순서대로 검증 가능한 단위로 진행한다: 개발 도구·빌드 기반 → 도메인·백업 상호 운용 → 저장·퀘스트 화면 → 연출·정산·설정 → 알림·파일 선택기 → 기기 검증·APK. 세부 파일과 테스트 명령은 이 명세 검토 후 구현 계획에 정리한다.
