# PENTAPHOR 한국어·영어 현지화 설계

## 목표와 승인된 방향

사용자가 한국어·영어 2개 언어, 영어 fallback, 기기 언어 기반 선택, 화면·알림·정산·스토어 문구 현지화를 요청했다. `~/dev/pentaphor`에서 직접 구현하고 테스트 후 내부 TestFlight Personal에 배포한다. 공개 심사 제출은 범위에 포함하지 않는다.

## 구조와 선택

Apple 기본 번들 현지화 리소스를 사용한다. 앱의 SwiftUI 문구와 Core의 파라미터 이름·오류·알림 문구를 각각 소유한 번들에 둔다. Core 패키지에는 리소스 처리와 명시적 locale로 검증할 수 있는 작은 조회 경계를 추가한다. 앱과 패키지의 기본 개발 언어는 영어이며 한국어 리소스를 제공한다. 서드파티 번역 SDK나 서버는 추가하지 않는다.

대안인 모든 화면의 언어별 조건문은 번역 누락과 복수형 관리가 어려워 제외한다. 별도 런타임 언어 저장 설정은 시스템의 앱별 언어 설정과 중복되므로 이번 범위에서 제외한다. 기본 언어 선택은 iOS가 지원 언어와 사용자 선호 언어 목록을 바탕으로 수행한다.

## 문구와 화면

홈, 생성·수정, 아트 선택·검색, 달성, 파라미터, 기록·보관, 시작 화면, 튜토리얼, 설정, 백업·복원, 알림, 주간 정산, CHALLENGE 구매·복원·해금, 오류·확인창과 접근성 레이블을 포함한다. 화면에 노출되는 동적 String도 번역 대상이다. 시스템 제공 오류 설명은 시스템 언어를 존중하고 앱이 덧붙이는 설명을 현지화한다.

브랜드명 PENTAPHOR, CHALLENGE, STACK YOUR PROGRESS와 기존 의도적인 영어 장식 문구는 유지한다. 영어는 짧고 직접적인 어조를 쓴다. 파라미터 이름은 Stamina / Knowledge / Perseverance / Charm / Courage로 통일한다. 한국어의 앱 정보·데이터 안내 존댓말과 나머지 친근한 어조를 유지한다. 영어 문구가 길어도 버튼·레이더 레이블·큰 글자가 잘리지 않도록 화면을 점검한다.

아트 ID와 분류 식별자는 그대로 두고 표시 이름·분류·검색 키워드만 현지화한다. 기존 사용자 퀘스트 이름·메모·닉네임은 번역하거나 덮어쓰지 않는다. 새 템플릿을 선택할 때만 현재 언어의 기본 문구를 제공한다. 아트만 바꿀 때 퀘스트 이름 힌트가 바뀌거나 아트 이름이 강제 노출되는 이전 동작을 다시 도입하지 않는다.

## 날짜, 수량, 데이터 보존

날짜·요일·시간·숫자는 locale에 맞게 표시하며 문장 단위 포맷과 영어 단복수 처리를 사용한다. 문장 조각 결합으로 어순을 고정하지 않는다. 구매 가격은 StoreKit Product.displayPrice를 사용한다.

표시 언어를 바꿔도 저장된 시간대, 주간 경계(월요일 00시), 지난주 기록 허용(월요일 09시 전), 정산 시점(월요일 09시 이후), 목표·완료 기록·획득 파라미터·구매 권한은 바뀌지 않는다. Codable raw value와 백업 스키마는 유지한다.

알림은 예약 시점의 앱 언어로 생성한다. 언어 변경 후 앱이 다시 실행되거나 활성화되면 기존 예약과 현재 언어 문구를 비교하여 다시 예약한다. 앱 실행 전에 이미 예약된 알림의 언어 변경까지 보장하지 않는다. 달성량을 채우면 알림을 중단하는 정책은 유지한다.

## 스토어 자료

영어 앱 소개·부제·프로모션 문구·키워드와 CHALLENGE 상품 이름·설명을 저장소에 준비한다. 실제 등록은 기존 한국어 메타데이터와 앱 정보 항목을 확인해 대응 가능한 필드에 적용한다. 작성에 필요한 지원 URL·개인정보 URL 등 사실 정보가 없으면 만들지 않고 남은 항목을 기록한다. 상품 가격·판매 지역·법적 계약은 변경하지 않으며 공개 심사에는 제출하지 않는다.

## 검증과 완료 기준

1. 한국어·영어 lookup, 미지원 언어 fallback, 수량 0/1/2/99, 동적 사용자 이름 보존, locale 날짜 표시를 테스트한다.
2. 언어가 달라도 동일한 입력에서 주간 기간과 파라미터 합계가 같고, 기존 백업을 그대로 복원할 수 있는지 확인한다.
3. 알림 문구 변경 후 재예약과 목표 달성 후 취소를 확인한다.
4. 양 언어 UI 테스트에서 홈→생성→달성, 설정·구매·복원 안내, 정산 흐름을 확인하고 한국어 회귀를 실행한다. UI 테스트의 고정 한국어 가정은 명시적 테스트 언어로 분리한다.
5. 번역 키 누락·원문 잔존을 점검하고 긴 영어·큰 글자 화면을 확인한다. DEBUG 샘플 데이터의 한국어는 사용자 데이터와 구분한다.
6. Core/native/UI 및 배포 스크립트의 요구 검증을 통과한 뒤 새 빌드를 업로드한다. Apple 처리와 Personal 설치 가능 상태를 확인하고 커밋·push한다.

## 설계 검토

기존 String 기반 공용 뷰, Core 오류와 예약 알림, 고정 ko_KR 날짜, 아트 검색 데이터까지 범위에 포함했다. 비즈니스 로직이나 저장 포맷을 변경하지 않고 표시 경계에만 현지화를 추가한다. 구현 계획에서 번들별 리소스 포맷과 테스트 파일을 구체화한다.
