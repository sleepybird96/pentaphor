# CHALLENGE 영구 해금 설계

상태: 사용자 명세 승인 완료(2026-09-30), 구현 계획 검토 대기. Android 작업은 사용자 요청으로 보류한다.

## 목적

무료로 충분한 성장 만족을 제공하고, 더 오래 사용할 사람이 성장 한계를 해금하도록 한다. 빠른 결제 전환은 목표가 아니다. 사용자 승인 방향은 무료 진행 중 퀘스트 8개·각 파라미터 99, CHALLENGE 해금 후 두 상한 모두 무제한, 한국 판매가 5,900원 한 번 구매다. 월 구독과 기존 PLUS 명칭은 사용하지 않는다.

이번 작업은 iOS 결제 기능과 해금 경험을 구현하고 TestFlight Personal에서 검증하는 것이다. 후속 App Store 출시 준비에 필요한 상품 정보·심사 설명을 함께 마련한다. 공개 출시의 소개 자료·개인정보 공개 내용·판매 지역·출시 시점은 별도 출시 작업에서 확인한다. 이 명세 승인이 공개 심사 제출이나 자동 출시를 의미하지 않는다.

## 상품과 화면

Apple 비소모성 인앱 구매 1개를 사용한다. 제안 상품 ID는 `app.pentaphor.personal.challenge.lifetime`. 외부에 생성하기 전 기존 상품을 확인하고 동일 목적의 상품이 있으면 재사용한다. 기준 국가는 한국, 의도한 가격은 5,900원이다. 실제 가격 포인트 존재 여부는 App Store Connect에서 확인한다. 다른 금액으로 임의 변경하지 않는다.

구매 화면은 다음 구성을 사용한다.

- 제목: CHALLENGE
- 설명: 99 너머의 성장을 해금해.
- 진행 중 퀘스트: 무료 8개 → 해금 ∞
- 각 파라미터 상한: 무료 99 → 해금 ∞
- 구매 버튼: StoreKit이 반환한 현지화 가격 + 영구 해금
- 보조 문구: 한 번 구매하면, 계속 사용할 수 있어.
- 성장 보존 안내: 99 이후의 성장도 쌓이고 있어. 해금하면 모두 반영돼.
- 구매 복원, 닫기, 이용약관·개인정보 안내 접근 경로.

가격 문자열을 앱 코드에 고정하지 않는다. 상품을 불러오지 못하면 구매 버튼을 비활성화하고 재시도·복원·닫기를 제공한다. ∞는 상한 설명에만 쓰고 실제 파라미터 값은 항상 숫자로 표시한다. VoiceOver는 ∞를 ‘무제한’으로 읽는다.

설정에서 언제든 해금 화면에 접근할 수 있다. 9번째 활성 퀘스트 추가 시 안내하고, 각 파라미터가 처음 99에 도달하면 달성 화면 안에 비차단 안내를 제공한다. 달성 직후 강제 구매 팝업을 띄우지 않는다. 해금 후 설정에 CHALLENGE 해금됨을 표시하며 별도의 모드 토글은 만들지 않는다.

아트·알림·주간 정산·메모·백업·복원은 무료에도 모두 제공한다.

## 원본 성장과 표시 성장

`QuestEngine.totals`와 완료 기록·보상·끈기 계산은 실제 누적값을 계속 유지한다. 상한은 데이터 삭제나 보상 차단이 아닌 표시 정책이다. 무료의 각 표시 값은 `min(raw, 99)`, 해금 후에는 raw다. 별도 초과 포인트 장부를 만들지 않는다.

메인·파라미터 상세·달성·정산의 오각형과 현재 파라미터 숫자는 같은 표시 정책을 적용한다. 무료 TOTAL GROWTH는 표시된 다섯 값의 합계다. 백업 파일은 실제 원본 기록을 담고, 미리보기에는 ‘누적 성장(상한 이후 포함)’이라고 명확히 표시한다.

달성 화면의 획득 보상은 실제 획득량을 유지한다. 예: 체력 98에서 +2이면 현재 값은 99, 보상은 +2, ‘상한 이후의 성장도 저장됐어’ 안내를 표시한다. 오각형 증가 배지는 표시 값의 차이(+1)를 쓰고 획득 보상과 구분한다. 99에서 완료해도 기록·보상·끈기·알림 목표 충족 계산은 정상 실행한다.

정산은 활동과 실제 획득 보상을 그대로 보고하며, 오각형 before/after만 상한을 반영한다. 초과분이 포함될 때 같은 성장 보존 안내를 표시한다. 구매나 구매 복원은 주간 보상·완료 횟수·끈기 보너스를 만들지 않는다.

기존 99 초과 사용자도 원본 수치를 보존한다. 무료 표시 정책으로 전환될 때 기존 성장이 삭제된 것으로 오해하지 않도록 한 번 안내한다. 백업 복원도 모든 원본 수치를 보존한다.

## 퀘스트 개수 정책

진행 중 개수는 기존 `activeQuests`와 동일하다: 삭제·보관·완료한 일회성은 제외, 이번 목표를 채운 주간·월간은 포함한다.

무료 상태에서 활성 수가 8 이상이면 생성과 활성으로의 보관 해제를 차단한다. 에디터 진입과 실제 저장 양쪽에서 검사하고, 결제창 취소로 작성 중 초안을 버리지 않는다. 기존 퀘스트 수정·완료·보관·삭제는 가능하다.

업데이트 전 데이터, 백업 복원, 완료한 일회성의 완료 취소로 8개를 초과할 수 있다. 데이터 복원과 취소는 제한하지 않는다. 기존 항목은 모두 사용 가능하며 8개 미만이 될 때까지 추가 생성·보관 해제만 제한한다. 결제 환불로 무료로 돌아와도 같은 정책이다.

## 결제와 권한

StoreKit 2를 사용하는 독립 PurchaseService를 둔다. UI와 개수 제한은 확인된 권한 상태를 읽고, 단위 테스트에서는 별도 가짜 서비스로 교체한다. 실제 배포에는 테스트용 해금 스위치를 넣지 않는다.

시작 시 거래 업데이트 감시를 연결하고 현재 유효한 거래를 확인한다. 상품 ID와 검증 결과가 유효한 비소모성 거래만 해금한다. 취소는 닫기 가능한 정상 결과, 승인 대기는 pending 안내, 실패는 재시도 가능한 오류다. 중복 탭을 막고, 성공 처리와 거래 완료를 멱등하게 만든다. 환불/취소된 권한 업데이트를 처리한다.

구매 복원은 사용자가 눌렀을 때 App Store 동기화 및 권한 재확인을 수행한다. 평소 실행에서 강제 로그인 창을 띄우지 않는다. 오프라인에는 기기의 검증 가능한 기존 StoreKit 거래를 사용한다. 단순 네트워크 실패를 확인된 권한 취소로 취급하지 않는다. 시작 권한 확인 전에는 무료/유료를 섣불리 표시하지 않고, 구매 유도와 제한 행동을 확인 완료까지 대기시킨다.

구매 권한은 사용자 백업 AppState에 넣지 않는다. JSON을 바꾸거나 다른 사람의 백업을 가져와서 해금되지 않아야 한다. 기기 교체 시 데이터 파일 복원과 Apple 구매 복원은 별개이며 안내도 구분한다. 원본 성장 데이터는 권한 상태와 무관하게 보존한다.

첫 버전은 앱 자체 계정·서버 없이 StoreKit으로 처리한다. 유료 계약·세금·은행 정보 등 계정 소유자의 입력이 필요한 상태가 발견되면 정확한 필요한 조치를 안내한다. 약관 동의나 민감한 금융 정보를 임의 작성하지 않는다.

## 해금 연출

검증된 구매로 무료→해금 상태가 되었을 때 한 번 재생한다. 거래 업데이트의 재전달로 반복하지 않는다. 구매 복원이나 재설치 후 권한 재확인은 간단한 복원 완료 안내를 사용한다. 화면 표시와 권한 확정은 분리하여 연출 도중 앱을 종료해도 구매가 사라지지 않는다.

약 1.2초 연출 제안:

1. 0~0.2초: 기존 오각형을 보여주고 두 상한의 99/8을 강조한다.
2. 0.2~0.4초: 상한 표기가 ∞로 전환되고 청록색 테두리가 퍼진다.
3. 0.4~0.95초: 오각형이 capped 값에서 실제 누적값으로 빠르게 성장하고 꼭짓점이 overshoot 후 안정된다. 저장된 실제 숫자로 카운트업한다.
4. 0.95~1.2초: CHALLENGE UNLOCKED와 ‘성장의 한계를 해금했어.’를 표시한다.

99 이하에서 구매해 실제 성장 차이가 없으면 장식적인 오각형 pulse만 사용하고 숫자는 그대로 유지한다. 99에서 100처럼 차이가 작아도 해금 pulse는 눈에 보이게 하고 최종 도형은 실제 기존 RadarGrowth 공식을 따른다. 한 축만 증가하면 나머지 축의 최종 크기는 변하지 않는다. 무제한은 도형이 화면 밖으로 커진다는 뜻이 아니다.

시스템 동작 줄이기 또는 앱 연출 간소화가 켜져 있으면 짧은 페이드와 최종 숫자로 대체한다. 햅틱 설정을 존중하고 검증된 해금에 한 번만 요청한다. 시작 로딩 연출에는 영향을 주지 않는다.

달성·정산·에디터·복원과 해금 화면이 겹치지 않도록 공통 표시 우선순위를 관리한다. 결제를 시작한 화면으로 안전하게 돌아오며, 보류 중인 정산은 해금 화면을 닫은 뒤 표시한다.

## 테스트와 전달

스펙 기반 TDD로 다음을 검증한다.

- 무료 7→8 생성 성공, 8→9 차단, 해금 후 생성 성공. 보관 해제·완료한 일회성·취소·초과 백업 복원·환불 경계.
- 98+2, 99+2, 한 축만 상한, 끈기 보너스 상한, 초과분이 있는 기록 취소, 표시 합계와 실제 합계 분리.
- 원본 백업 호환, 권한을 포함하지 않는 복원, 기존 99 초과 데이터 비파괴 마이그레이션.
- StoreKit Test: 성공/취소/pending/실패/미검증/중복 업데이트/복원/환불/재시작/상품 로딩 실패.
- 연출: 초과 성장 있음·없음·한 축만 증가, reduced motion·간소화·햅틱 꺼짐, 재전달 중복 방지, 정산과 충돌 방지.
- UI: 구매 취소 후 초안 보존, 설정 복원 경로, 실제 가격 표시, VoiceOver 무제한, 모든 통계 화면의 일관된 상한.

로컬 StoreKit 설정과 주입 가능한 테스트 시나리오로 99 이상을 즉시 검증하고 데모 영상을 만든다. 사용자의 실제 기록을 테스트용으로 수정하지 않는다. 로컬 시뮬레이션과 TestFlight sandbox 구매, 실제 판매 가능 상태를 구분해 보고한다.

구현 완료 후 기존 회귀 테스트와 빌드 검증을 실행하고 `python3 scripts/testflight.py deploy`로 새 빌드를 Personal에 배포한다. 처리 지연은 status 명령으로 이어서 확인하고 설치 가능 상태를 확인한 뒤 보고한다. 첫 인앱 구매는 App Store 출시 시 앱 버전과 함께 심사하도록 상품 설명·심사 메모·스크린샷을 준비한다.

## 연결할 기존 구성

- Core: 표시/이용 제한용 순수 ChallengePolicy 추가. QuestEngine의 원본 totals와 파일 형식은 보존한다.
- App: PurchaseService, 해금 표시 coordinator, 거래 검증 adapter 추가. QuestStore 변경 진입점과 연결한다.
- Views: QuestEditor/QuestHome/JournalViews/ParameterRadar/AchievementView/WeeklyRecapView/SettingsView/BackupSettingsView에 일관된 표시 정책을 연결한다.
- Tests: 정책 단위 테스트, StoreKit Test, 해금 연출·구매 복원 UI 테스트.
- 출시 준비 문서: 상품 ID·가격·유형, 기능 설명, 무료 제한과 숨겨진 성장 보존, 복원 경로 및 심사자 테스트 방법.
