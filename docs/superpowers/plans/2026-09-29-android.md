# PENTAPHOR Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 PENTAPHOR와 데이터·동작이 호환되는 네이티브 Android 앱을 테스트하고 설치 가능한 APK로 제공한다.

**Architecture:** 같은 저장소의 `android/core`는 순수 Kotlin 도메인과 파일 형식을 담당한다. `android/app`은 Compose 화면과 Android 저장·알림·햅틱을 연결한다. Swift 구현을 기준으로 한 고정 fixture로 플랫폼 간 동등성을 검증한다.

**Tech Stack:** Kotlin, Jetpack Compose, java.time, kotlinx.serialization JSON, coroutines/StateFlow, Android AtomicFile, AlarmManager, WorkManager, Storage Access Framework, JUnit/Compose UI tests.

**Spec:** `docs/superpowers/specs/2026-09-29-android-design.md` (사용자 승인 완료).

## Global Constraints

- 최소 Android 8.0(API 26), 앱 ID `app.pentaphor.personal`, 표시 이름 PENTAPHOR.
- 슬로건 `STACK YOUR PROGRESS` / `작은 행동을 쌓아, 나를 키우다`.
- 체력·지식·끈기·매력·용기, 퀘스트 보상 총합 최대 2, 목표 1~99, 일회성 목표 1.
- 새 주 월요일 00시, 지난주 명시적 기록은 월요일 09시 전, 정산은 09시 이후.
- 기존 60종 아트와 최종 로고 재사용. 아트 변경은 이름·힌트를 변경하지 않는다.
- `.pentaphor` v1, 전체 파일 20 MiB 제한, 원본 payload 바이트 SHA-256.
- 저장 성공 후 상태 게시·햅틱·알림 재계산. 복원 전 안전 사본 저장.
- 서버·로그인·자동 동기화·Google Play 배포는 추가하지 않는다.
- Android 서명 키는 `~/.config/deploy-credentials/android/pentaphor/`에만 보관한다.
- iOS 제품 소스·서명·배포 설정은 변경하지 않는다. Android만 변경하면 TestFlight 업로드 없음.
- 각 작업은 red → green → 필요한 리팩터링 → 해당 파일만 커밋. 무관한 untracked 에셋은 건드리지 않는다.

## Review Focus

1. 한글 조합형·가족 이모지 이름: UTF-16 길이로 잘못 거부하지 않도록 Swift 문자 길이 fixture로 검증한다(Task 1).
2. 복원과 완료가 동시에 요청됨: 이전 상태의 완료가 복원 이후 끼어들지 않고 저장 실패 시 기존 상태를 보존한다(Task 5).
3. 파일 제공자가 크기를 모르거나 중간에 끊김: 스트림 읽기 중 크기 제한, 취소·I/O 실패 시 원본 상태 보존(Task 9).
4. 알림 예약 후 목표 달성 또는 복원: 오래된 수신 이벤트가 알림을 보내지 않으며 미래 구간을 계속 예약한다(Task 8).
5. 날짜가 다른 구간으로 넘어가는 동안 편집/정산: 저장·표시 시 현재 시간을 재평가하고 같은 정산을 중복 표시하지 않는다(Task 6/7).

## 작업 경계와 도구 버전

실행 시작 시 `using-git-worktrees` 절차로 적합한 checkout을 확인하고 필요 시 격리한다. 문서 검토 단계에서는 설치나 scaffolding을 실행하지 않는다.

빌드 도구 기준은 JDK 17, AGP 9.1.1, Gradle 9.3.1, Kotlin 및 Compose compiler plugin 2.2.10, Compose BOM 2026.09.00이다. AGP 내장 Kotlin을 app에서 사용하고 core는 Kotlin JVM plugin을 사용한다. JSON/coroutines/AndroidX의 BOM 밖 의존성은 Task 1의 최소 빌드에서 공식 안정 버전을 확인하여 `libs.versions.toml`에 고정하고 Gradle dependency lock을 커밋한다. 호환성 문제로 기준 조합을 바꾸면 사유와 검증 결과를 이 문서에 기록한다.

SDK는 Task 1에서 `sdkmanager --list`에 노출된 가장 높은 정수 stable API를 compile/target으로 고정한다(preview 제외). AGP가 지원하는 상한을 넘으면 공식 호환 AGP를 먼저 선정하고 기록한다. JDK는 `~/Library/Java/JavaVirtualMachines/`, SDK는 `~/Library/Android/sdk`에 둔다. 다운로드는 공급자 checksum을 검증하고 환경 변수는 프로젝트 실행 스크립트에서만 지정한다.

근거: [AGP 호환표](https://developer.android.com/build/releases/agp-9-1-0-release-notes), [내장 Kotlin](https://developer.android.com/build/migrate-to-built-in-kotlin), [Compose BOM](https://developer.android.com/develop/ui/compose/bom). BOM은 Compose compiler 버전을 정하지 않으므로 compiler plugin은 Kotlin 버전과 맞춘다.

경로 약칭(아래 모든 파일은 이 경로에 상대적):

- **C** = `android/core/src/main/kotlin/app/pentaphor/core/`

- Gradle 명령은 저장소 루트에서 `./android/gradlew -p android ...`로 실행한다.

## 계획 자체 검토

모든 명세 항목을 Task 1~10에 배치했다. 특히 데이터 유실 방지(Task 4/5/9), 독립적인 축 성장과 시작 연출(Task 3/7), 지난주 유예와 목표 즉시 수정(Task 2/6), 백그라운드 알림 복구(Task 8), 실제 업데이트 설치(Task 10)를 각각 검증한다. 플랫폼 SDK 버전은 설치 목록으로 확정하는 명시적 단계이며, 사용자가 결정해야 할 기능 요구사항은 남기지 않았다.

**실행 방식 제안:** 이 세션에서 순서대로 직접 구현하는 Native 방식. 도메인 모델→저장→화면→플랫폼 연결의 의존성이 강하므로 한 구현자가 이어서 작업하고, 마지막에 독립 리뷰어가 전체 변경을 점검하는 편이 문맥 중복을 줄인다. 사용자가 단계별 독립 검토를 선호하면 Subagent-driven 방식으로 각 Task 구현/리뷰를 분리할 수 있다. 구현 계획 검토와 실행 방식 선택 후 시작한다.
